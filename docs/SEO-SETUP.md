# SEO & GitHub Pages Setup (One-Time, Manual)

This file documents the **one-time manual steps** the repository owner must
perform to activate GitHub Pages and maximize Google discoverability.
Everything in the repo itself (Jekyll site, sitemap, robots.txt, workflow,
English docs) is already prepared.

---

## 1. Enable GitHub Pages (Settings)

1. Go to **Settings → Pages** in
   [lxndrJ/TDisplayS3_Adventure](https://github.com/lxndrJ/TDisplayS3_Adventure).
2. Under **Build and deployment → Source**, select **GitHub Actions**
   (NOT "Deploy from a branch" - the repo ships a ready-made
   `.github/workflows/pages.yml`).
3. Save. The workflow runs automatically on the next push to `main`
   (or manually via **Actions → Deploy Docs to GitHub Pages → Run workflow**).

> The first deploy happens after this PR is **merged to `main`**.
> The site will be live at:
> **https://lxndrJ.github.io/TDisplayS3_Adventure/**

## 3. Upload a Social Preview Image (Settings → General → Social preview)

Upload a **1280 x 640 px** PNG/JPG. Suggested content:

- Dark cyberpunk background with neon accents (cyan `#00F0FF`, magenta `#FF2BD6`)
- Text: **"TDisplayS3 Adventure"** + subtitle "Mini-Game Platform for LilyGo T-Display-S3"
- Maybe small screenshots of the 5 games as thumbnails

This image appears when the repo / Pages site is shared on social media
and in link previews - it significantly improves click-through rate.

A quick way to generate one (if you have Python + PIL):

```python
from PIL import Image, ImageDraw, ImageFont
img = Image.new("RGB", (1280, 640), (11, 14, 20))
d = ImageDraw.Draw(img)
# ... draw neon title text, game names, etc.
img.save("social-preview.png")
```

Then upload it in **Settings → General → Social preview → Upload an image**.

## 4. Submit the Sitemap to Google Search Console

After the Pages site is live (step 1) and reachable:

1. Go to [Google Search Console](https://search.google.com/search-console).
2. **Add property** → **URL prefix**: `https://lxndrJ.github.io/TDisplayS3_Adventure/`
3. Verify ownership (GitHub Pages serves a `google-site-verification`
   meta tag only if you add it - alternative: verify via the GitHub repo
   DNS/HTML method, or use the **Domain** property type if you own a domain).
   - Simplest for a `*.github.io` subpath: use the **HTML file** method
     is NOT possible on Pages; instead verify via **DNS** if you add a
     custom domain, or use the **HTML tag** method by adding the
     `google-site-verification` meta tag to `docs/_layouts/default.html`
     (see below).
4. Once verified, go to **Sitemaps** and submit:
   `https://lxndrJ.github.io/TDisplayS3_Adventure/sitemap.xml`
   (auto-generated by the `jekyll-sitemap` plugin).

### Optional: Google verification meta tag

If Google asks for an HTML-tag verification, add this line to
`<head>` in `docs/_layouts/default.html` and `docs/_layouts/home.html`:

```html
<meta name="google-site-verification" content="YOUR_VERIFICATION_CODE" />
```

## 7. Optional: Custom Domain (for even better SEO)

If you ever buy a domain (e.g. `tdisplays3-adventure.dev`):

1. Add a `docs/CNAME` file containing just the domain:
   ```
   tdisplays3-adventure.dev
   ```
2. In your DNS provider, add:
   - `A` records pointing to GitHub Pages IPs:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - or a `CNAME` record: `www` → `lxndrJ.github.io`
3. In **Settings → Pages → Custom domain**, enter the domain and enable
   **Enforce HTTPS**.
4. Update `url:` in `docs/_config.yml` and the sitemap URL in `docs/robots.txt`.

A custom domain ranks better than a `*.github.io` subpath because it
looks more "established" to Google.
